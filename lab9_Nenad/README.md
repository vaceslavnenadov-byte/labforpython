# ЛР №9 — TCP/UDP, клиент-серверная архитектура, прикладной протокол

**Вариант 10. Отель** — сущность `Room`, специализированная команда `find_free` (поиск свободных номеров).

```
Client ──TCP (NDJSON)──► Server ──► RoomService ──► RoomRepository (память)
Client ──UDP "status"──► Server (порт +1)
```

Запуск: `python server.py --port 5000`, затем в нескольких терминалах `python client.py --port 5000`.
Тесты: `python -m pytest -v` (17 тестов, включая интеграционный TCP и UDP).

## Протокол (newline-delimited JSON)

Запрос: `{"request_id": "a1b2", "command": "...", "data": {...}}\n`
Ответ: `{"request_id": "a1b2", "status": "ok", "data": ...}` или `{"status": "error", "error": "..."}`.

| Команда | data | Назначение |
|---|---|---|
| list | {} | список номеров |
| get | {id} | номер по id |
| create | {number, room_type, floor, price, capacity} | создание |
| update | {id, ...поля} | изменение |
| delete | {id} | удаление (нельзя удалить занятый) |
| **find_free** | {room_type?, min_capacity?, max_price?} | поиск свободных номеров |
| check_in / check_out | {id, guest} / {id} | заселение / выселение |
| stats | {} | статистика загрузки |
| ping | {} | pong + измерение RTT |
| history | {} | последние 20 запросов |
| sleep | {seconds} | отладка: демонстрация тайм-аута клиента |
| shutdown | {token} | корректная остановка сервера (токен `HOTEL_ADMIN_TOKEN`, по умолчанию `admin`) |

## Что реализовано
* Многопользовательский сервер на `ThreadPoolExecutor`; `RLock` в репозитории исключает гонки (два клиента не заселятся в один номер — проверено тестом).
* Границы сообщений: `MessageReader` буферизует поток TCP и делит его по `\n`.
* Тайм-ауты: клиент 5 с (пункт 13 меню демонстрирует срабатывание), сервер отключает клиента после 120 с бездействия.
* Ошибки: недоступный сервер, разрыв соединения, неизвестная команда, некорректный JSON, нет обязательных полей, объект не найден, неверные значения, тайм-аут. Исключения: `ProtocolError`, `RoomNotFoundError`, `ValidationError`, `ConflictError`.
* `logging`: запуск, подключение/отключение, команды, ошибки.
* Доп. задания: UDP-статус, `ping`, `request_id`, rate limiter (10 запросов / 10 с), история запросов, graceful shutdown.

UDP для статуса допустим: это быстрый неважный запрос; если датаграмма потеряется, клиент просто повторит его.
