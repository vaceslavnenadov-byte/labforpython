# ЛР №7 — Принципы SOLID и рефакторинг

**Вариант 10. Железнодорожные перевозки:** поиск рейса, бронирование, покупка, возврат билета; несколько способов оплаты.

* `v1_bad/railway_app.py` — рабочая версия с намеренными нарушениями (`python railway_app.py`).
* `v2_solid/` — версия после рефакторинга (`python main.py`, тесты: `python -m pytest -v`).

## Найденные нарушения и их исправление

| № | Проблема в v1 | Принцип | Решение в v2 |
|---|---|---|---|
| 1 | `RailwayManager` хранит данные, ищет, бронирует, принимает оплату, шлёт уведомления, печатает отчёт и пишет в консоль | SRP | `SearchService`, `BookingService`, `ReportService`, репозитории, `ConsoleUI`, `Notifier` |
| 2 | `buy()` содержит `if payment_type == "card" / "cash" / "sbp"` | OCP | Абстракция `PaymentMethod` + `CardPayment`, `CashPayment`, `SbpPayment`, `BonusPayment` (добавлен без изменения сервиса) |
| 3 | `ConcessionTicket.refund()` бросает исключение, хотя базовый класс обещает возврат | LSP | Подклассы билетов убраны; различия вынесены в данные `Tariff(discount, refund_share)` |
| 4 | Интерфейс `TicketOperations` с `send_sms`, `export_to_xml` и т. п.; реализации бросают `NotImplementedError` | ISP | Маленькие протоколы `TripReader`, `TripWriter`, `TicketReader`, `TicketWriter`; `ReportService` зависит только от чтения |
| 5 | `self.storage = FileStorage()` внутри менеджера | DIP | Конструкторная инъекция репозиториев и `Notifier`; инъекция в метод для `PaymentMethod`; выбор реализации в `main.py` |
| 6 | `print()` внутри бизнес-логики, невозможность тестирования | SRP/DIP | Сервисы возвращают данные, печать только в `ui/console.py`; 12 тестов pytest с `FakeNotifier` |

## Сравнение

| Характеристика | До | После |
|---|---|---|
| Ответственность классов | один «божественный» класс | 1 класс — 1 задача |
| Зависимости | жёсткие (`FileStorage()`) | абстракции + DI |
| Расширяемость | правка `if/elif` | новый класс |
| Тестируемость | только вручную через консоль | 12 автотестов без I/O |
| Использование абстракций | нет | Protocol, ABC |

Доп. задания: две реализации репозитория (память / JSON-файл, выбор при запуске), контейнер зависимостей `container.py`.
