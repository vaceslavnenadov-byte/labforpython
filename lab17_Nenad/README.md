# ЛР №17 — Асинхронный Telegram-бот на aiogram 3

**Вариант 10. Железнодорожные билеты**: сущности *станция*, *поезд*, *пассажир (пользователь)*, *билет*.
Функции: расписание, поиск маршрута, бронирование билета, история поездок (мои билеты), изменение и возврат.

## Запуск
```bash
pip install -r requirements.txt
cp .env.example .env        # вписать BOT_TOKEN от @BotFather и свой Telegram id в ADMIN_IDS
python bot.py               # polling; при первом запуске создаётся railway_bot.db с тестовыми данными
python -m pytest -v         # 23 теста (без подключения к Telegram)
```

## Архитектура
```
Telegram → Dispatcher ─► LoggingMiddleware → ServiceMiddleware (сессия БД, регистрация пользователя)
                      └► Routers: start, admin, schedule, booking (FSM), tickets, common
                              ↓
                         RailwayService (services/) → Repositories (database/) → SQLAlchemy async → SQLite
```
| Папка | Содержимое |
|---|---|
| `handlers/` | обработчики команд, кнопок, FSM; только взаимодействие с Telegram |
| `keyboards/` | Reply-меню и Inline-клавиатуры, `CallbackData` (`train:book:5`, `wagon:sv`, `ticket:return:12`, `confirm:yes`) |
| `states/` | `BookingStates` (7 состояний), `RenameStates` |
| `services/` | бизнес-логика `RailwayService`, проверка ввода `validation.py` |
| `database/` | модели, асинхронный движок, репозитории, тестовые данные |
| `middlewares/` | журналирование (пользователь, действие, время, счётчик команд) и внедрение сервиса |

## Возможности
* Команды: `/start`, `/help`, `/cancel`, `/schedule`, `/search`, `/buy`, `/mytickets`; админ: `/admin`, `/users`, `/statistics`.
* Главное меню (Reply Keyboard, 5 пунктов): Расписание, Найти поезд, Купить билет, Мои билеты, Помощь.
* Inline-кнопки с id объекта: выбор поезда, типа вагона, подтверждение, действия с билетом.
* FSM покупки: откуда → куда → поезд → тип вагона → место → ФИО → подтверждение. `/cancel` в любой момент.
* Валидация: город (пустой, цифры), совпадение городов, номер места (не число, вне диапазона, занято), ФИО,
  не-текстовые сообщения в сценарии, устаревшие кнопки.
* CRUD через Telegram: создание (покупка), просмотр (мои билеты), изменение (ФИО пассажира), удаление (возврат 90%).
* БД: 10 станций, 16 поездов, 6 пользователей, 12 билетов; уникальный индекс «одно место — один действующий билет».
* Администратор (id из `ADMIN_IDS`): список пользователей, статистика (пользователи, сообщения, поезда, билеты,
  выручка, самое популярное действие); обычный пользователь эти команды не видит.

## Почему asyncio
Бот большую часть времени ждёт ввода-вывода (сеть Telegram, база данных). `await` отдаёт управление event loop,
и пока один запрос ждёт ответа БД, обрабатываются сообщения других пользователей. Корутина (`async def`) —
функция, которую можно приостановить и продолжить; обычная функция выполняется до конца без пауз. Блокирующий
вызов (например, `time.sleep` или синхронный драйвер БД) остановил бы весь цикл и всех пользователей, поэтому
используется асинхронный SQLAlchemy с драйвером `aiosqlite`.

## Тесты
`tests/test_validation.py` — проверка ввода; `tests/test_service.py` — бизнес-логика (поиск, покупка, повторная продажа
места, изменение, возврат, права); `tests/test_bot_flow.py` — сквозные сценарии через `Dispatcher.feed_update`
с подменённой HTTP-сессией (полный FSM покупки, `/cancel`, устаревшая кнопка, права администратора).
